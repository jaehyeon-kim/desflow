    Replications

    One run of a model is one sample: another seed draws other times and gives other values. Replications run the same model with many seeds and summarise each built-in statistic with a mean and a 95% interval. This page shows how to run them from the command line and from Python, in each of the three ways to write a model, what they return and send to the sinks, and how the seeds and intervals are made.

    What It Is

    A replication is one run of the model with a seed of its own. N replications give N independent values of each built-in statistic, such as the mean wait of a task. Their mean is the estimate, and the half-width of its 95% interval says how precise it is: with 95% confidence, the true value lies within the mean plus or minus the half-width. Trusting Results shows on the shop why one run is not an answer and how to choose the number of replications.

    How to Use It

    Run Replications

    Give the model, the number of replications, the seed they are spawned from and the time the arrivals stop:

    1
    desflow run replications.yaml --replications 20 --measure tasks.pack.wait_mean

    --seed overrides simulation.random_seed, and --until overrides run.until, as for one run. --level sets the confidence level (0.95 when it is not given), --workers sets how many replications run at once, each in its own process, and --drain drains every replication, as run.drain: true does. The command prints the summary, the seed of each replication and the command that repeats one. The blueprint's own warmup applies to every replication:

    examples/yaml/replications.yaml:seed
    1
2
3
    # The replications' seeds are spawned from this one; --seed overrides it
random_seed: 42
warmup: 3 min
    docs/snippets/pages/replications.py:builder
    1
2
    # shop is a function returning a new SimulationContext, called once per run
result = replicate(shop, 3, seed=42, until="1 h", warmup="3 min", measures=MEASURES)

    shop is a function with no arguments that returns a new SimulationContext, such as the example's, because each replication starts from a new context. A blueprint path works here too.

    def model(env, sampler):
    """Builds the shop in the environment it is given, drawing from sampler."""
    env.registry.register_sim_parameter(PARAMS)
    env.process(orders(env, sampler, DynamicResource(env, "Shop", "packers")))

    return replicate(shop, 3, seed=42, until=3600, warmup=180, measures=MEASURES)

    LowLevelModel takes a function that builds the model, given an environment and a sampler, and the sim_id that the model's statistics are published under. The function registers the parameters, builds the resources and starts the processes. It sets up no statistics, because replicate does, and it sets up no sinks. Its tasks report their steps to env.stats, as Statistics shows.

    replicate takes these options:

    Option What it sets Default
    n how many replications, 2 or more
    seed the seed the replications' seeds are spawned from; None draws one and logs it
    until where each replication's arrivals stop, in seconds or a duration such as "1 h"; the replication ends there unless stop ends it earlier or drain runs on a blueprint's run.until
    stop ends each replication when it happens, as for run(): {"signal": name}, a signal's name, or {"condition": "..."}; for a LowLevelModel, a function of the environment that returns the event a blueprint's run.stop
    drain at until, stop the arrivals and run each replication on until no entity is left: True, or {"limit": "1 h"}; a LowLevelModel is drained when its function returns its arrival processes and reports its entities with env.stats.flow_started and flow_finished a blueprint's run.drain
    warmup the end of each replication's warm-up the model's own
    measures the statistics to summarise every statistic the run publishes, at least up to typical
    level the confidence level of the half-widths 0.95
    workers how many replications run at once, each in its own process 1
    overrides registry paths and the values every replication starts with, such as {"Shop.resources.packers.current_cap": 3}, set in the order given; a value the registry would refuse or clamp is refused, so a max_cap below the current current_cap needs current_cap set first none

    Choose the Measures

    A measure is a statistic's published name without the sim id and stats, such as tasks.pack.wait_mean for Shop.stats.tasks.pack.wait_mean. Reference, Statistics lists them. Each replication keeps the statistics level its measures need, whatever level the model sets: basic for counts and time averages, typical for means and maxima of waits and services, and all for percentiles. A higher level the model sets stays.

    A name that no replication publishes is refused, with the names the model does publish. A count that is published only once it is above 0, such as reneged, is 0 in a replication without one. A mean with no observation in a replication, such as the wait of a task that never started, is refused with the replication's number rather than left out.

    Read the Result

    replicate, imported with from desflow import replicate, returns a Replications. Its summary has one row per measure: a mapping with measure, n, mean, half_width and level. The interval runs from mean - half_width to mean + half_width. Its table has one row per replication and measure, with the replication's number and seed, and seeds lists the seeds in order:

    docs/snippets/pages/replications.py:read

    print(result.summary_text())  # each measure's n, mean and half-width
for row in result.summary:  # measure, n, mean, half_width and level
    low, high = row["mean"] - row["half_width"], row["mean"] + row["half_width"]
    print(f"{row['measure']}: {low:.2f} to {high:.2f} ({row['level']:.0%})")
print(result.seeds)  # replication i ran with seeds[i - 1]
for row in result.table:  # one row per replication and measure
    print(row["replication"], row["seed"], row["measure"], row["value"])

    Repeat One Replication

    Each replication's seed is a plain integer, recorded in seeds and in every row of the table. Any replication can therefore be repeated on its own, with the same end time, drain and warm-up: desflow run shop.yaml --seed <its seed>, random_seed in a builder context, or Sampler(seed=...) in the low-level API. That run publishes its event records, which replications do not.

    What the Sinks Receive

    How It Works

    Seeds. The replications' seeds are numpy.random.SeedSequence(seed).spawn(n), each turned into one plain integer. The same seed gives the same list, and a longer list starts with the shorter one, so 40 replications begin with the 10 that n=10 runs. Within a replication each distribution draws from a random sequence of its own, as in any run (Randomness and Seeds).

    One replication. Each replication builds the model again: it reads the blueprint, calls the factory, or calls the low-level function with a new environment and sampler. It runs unpaced, at factor 0, with no ingress, no egress and no statistics timer. It applies the warm-up and the overrides before the clock starts, and reads env.stats.readings() at its end. A blueprint's run.before functions run once per replication, and once more when the model has sinks, for the build that sends them the result.

    Intervals. The half-width is t × s ÷ √n. Here s is the sample standard deviation of the n values, and t is the Student t quantile at (1 + level) ÷ 2 with n − 1 degrees of freedom. desflow computes the quantile itself, by bisection on the t distribution's cumulative probability, so replications need nothing beyond a base install. The tests check it against a published table.

    Workers. With workers above 1, replications run in a pool of that many processes. Each process imports the model. The model must therefore be a blueprint path or a function defined at the top of a module. A lambda, or a function defined inside another function, is refused with that reason. The values are the same as with one worker.

    Sinks. When the model has sinks, it is built once more after the last replication, with its sinks, without its ingress, and with the clock at the end time. This build is not run. Its own statistics are switched off, so the sinks receive only the result. A model without sinks is not built again.

    Stability and Limits

    • No event records. Replications send no event records: the orders of twenty replications, each with its own seed, would mix in one sink and could not be told apart. Repeat one replication with its seed to get its records.
    • Independent seeds only. Every replication of one call has its own seed. Comparing two designs with the same seeds, and checking that their random streams line up, is an experiment's job (Experiments).
    • Same model each time. A builder factory must return a new context on every call. A context that has run keeps its entity counters and is not a new replication.
    • Built-in statistics only. A replication summarises the built-in statistics at its end. Readings of your own, published with context.publish, are not summarised.
    • Steady state and terminating runs. The warm-up applies to each replication. A run with a natural start and end, such as a shop day, keeps its empty start and needs no warm-up. Output Analysis explains the two kinds of run.

    Example: Replications

    The replications example runs one hour of the shop 20 times, with seeds spawned from 42 and a 3-minute warm-up, and prints the mean and half-width of every statistic up to typical. It needs no Docker service and ends on its own.
