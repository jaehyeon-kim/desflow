`blueprint.schema.1.0.json` is the JSON Schema of the YAML blueprint format as 1.0 froze it. It is the 1.0 contract, a copy of `src/desflow/blueprint/blueprint.schema.json` at the end of Batch 12 part 12d1, and it is never regenerated. `tests/unit/test_yaml_format_frozen.py` compares the committed schema with it, and every difference must be a listed widening.

`cli.1.0.json` is the `desflow` command line as 1.0 froze it, in two sections, made once from the Typer app at the end of Batch 12 part 12d2, with Typer 0.27.3 as `uv.lock` holds it, and never regenerated after that part's commit. "description" holds the declared attributes of every command, group, parameter and parameter type, that is the arguments that Click documents for their constructors, as the literal tuples of `tests/unit/test_cli_surface.py` list them, with the module and qualified name of each class; nothing else is recorded, so a Typer or Click release that changes only internals changes nothing here. The test compares it with the current app, and every difference must be a listed widening. When a Click or Typer release renames or moves what the tuples name, the test fails and says what to check; the change is then recorded in `TYPER_CHANGES` in the test, never in this file. "commands" holds, for each command and group, a list of argument lists and what Click parses each to (the parameter values by name, the exit code of `--help` and `--version`, or the kind of error when 1.0 refuses the list); the test replays every list, and a list that 1.0 accepts must parse to the same values, with the same types. A check inside a command or a callback, such as `parse_until` for `--until`, is outside this file and this test.
